# US-022: Save a selection with its images as one note

The extension must stop relying on `info.selectionText`, which is plain text, and read the
selected DOM instead. Images become markdown images at their position in the selection, and
their bytes are uploaded with the note.

## Decisions

- **Read the selection in the page.** Add the `"scripting"` permission and call
  `browser.scripting.executeScript` with `target: { tabId: tab.id, frameIds: [info.frameId] }`
  so a selection inside an iframe works. `info.selectionText` stays as the fallback when
  injection is refused, for example on a browser-internal page.
- **The injected function is self-contained.** `executeScript({ func })` serializes the
  function, so it cannot import or close over module state. Keep the DOM walker in the injected
  function and test it by importing the same source in Node.
- **One note, markdown in document order.** Walk the cloned `Range` contents:
  - text nodes contribute their text;
  - `<br>` contributes a newline;
  - block elements (`p`, `div`, `li`, `h1`–`h6`, `blockquote`, `pre`, `tr`) contribute a
    blank line between blocks;
  - each `<img>` becomes `![alt](@stash-image-N)`, numbered from zero in selection order;
  - `<script>`, `<style>`, and `<noscript>` are skipped.
- **Inline formatting is flattened in v1.** Bold, italic, and links inside the selection
  become their text. Only line structure and images are preserved. Preserving inline marks is
  a follow-up, not part of this story.
- **Image address.** Use `img.currentSrc || img.src`, resolved against `document.baseURI` so a
  relative `src` becomes absolute. Skip an image with no usable address.
- **`blob:` images are read in the page.** The background cannot fetch a page's `blob:` URL.
  The injected function reads the blob and returns a data URL. This needs the function to be
  async and the browser to await it; verify on Chrome and Firefox, and fall back to the
  remote-URL behaviour if a browser does not.
- **Download failures fall back to the address.** The background downloads each image. A
  failed download is replaced with its absolute URL in the markdown, so the text and the order
  still survive.
- **Placeholders are renumbered after the downloads.** The page numbers every image; the
  background decides which ones upload. It rewrites each `@stash-image-N` to
  `@stash-image-k` for the k-th successful upload, and to the absolute URL for a failure. The
  server replaces placeholders by their index in the `images` field, so the numbers must be
  contiguous and match the upload order.
- **No images keeps today's path.** When the selection has no images, keep posting JSON
  `{body}` with `saveText`. Only use multipart when at least one image is present.
- **Limits are the server's.** 10 images per note, 25 MB per image. The extension can warn
  before uploading, but the server remains the authority.

## Codebase patterns to follow

- Menu and dispatch: `extension/src/menu.js`, `extension/src/dispatch.js`
  (`save-selection` currently calls `saveText(info.selectionText)`).
- API: `extension/src/api.js` (`postJson`, `saveText`, `saveImage`); the web equivalent is
  `captureNote` in `web/src/lib/api/client.ts`.
- Manifest permissions: `extension/manifest.json` (`contextMenus`, `storage`, `identity`,
  host `<all_urls>`).
- Build: `extension/scripts/build.mjs` copies `runtimeDirs`; the manifest is generated by
  `extension/scripts/manifest.mjs`.
- Placeholder replacement already exists server-side in
  `server/internal/api/use_cases/item/handler.go` (`captureNote`).
- Test harness: `extension/test/dispatch.test.js`, `extension/test/webext-mock.js`.

## Tasks (dependency order)

### Phase 1 — permission and selection reader

1. Add `"scripting"` to `permissions`. Confirm `web-ext lint` on the Firefox build accepts it
   and that `<all_urls>` host permission still covers injection.
   - `extension/manifest.json`, `extension/scripts/manifest.mjs` if it edits permissions
2. Write the injected reader as one self-contained function that returns
   `{ markdown, images: [{ src, alt }] }`. Include the DOM walker, image numbering, block
   spacing, and the `blob:` → data URL read.
   - `extension/src/selection.js` (a named export the dispatcher passes to `executeScript`)
3. Add a pure function that turns a `DocumentFragment` into `{ markdown, images }`, and unit
   test it with jsdom-style fixtures: text only, image between paragraphs, image only, two
   images, relative `src`, nested inline elements, a skipped `<script>`.
4. Make the reader fail soft: no selection, an inaccessible frame, or an injection error
   returns nothing so the dispatcher can fall back to `info.selectionText`.

### Phase 2 — image download and upload

5. Add `downloadSelectionImages(images)` to the background. For each entry, fetch the `src`,
   check `response.ok`, and build a `File`/`Blob` with a name from the URL path. Return one
   result per image: `{ ok, blob, name }` or `{ ok: false, src }`.
6. Add `resolveImageTokens(markdown, results)` that rewrites `@stash-image-N` to contiguous
   `@stash-image-k` for successful downloads and to the absolute `src` for failures. Return
   both the markdown and the ordered blobs for the form. Unit test the mixed case where the
   first image fails and the second succeeds.
7. Add `saveNote(markdown, images)` to `api.js`: build `FormData` with `markdown` and repeated
   `images`, `POST /items`, parse the envelope. Keep `saveText` for the no-image case.
8. Wire `save-selection` in `dispatch.js`:
   - inject the reader with `info.frameId`;
   - if it returns nothing, fall back to `saveText(info.selectionText)`;
   - if there are no images, `saveText(markdown)`;
   - otherwise download, resolve tokens, and `saveNote`.
   Keep the existing success and failure badges.

### Phase 3 — tests and docs

9. Extend the browser mock with `scripting.executeScript` returning a controllable result, and
   stub `fetch` for image downloads.
   - `extension/test/webext-mock.js`
10. Dispatch tests: selection with images creates one multipart request; a failed image falls
    back to its URL without losing the text; a selection with no images still posts JSON; an
    injection failure uses `info.selectionText`.
    - `extension/test/dispatch.test.js`
11. Update the extension docs: the new permission shown at install, and what "Save selection"
    now captures.
    - `docs/chrome-extension.md`, `docs/firefox-extension.md`
    - `site/content/docs/chrome-extension.md`, `site/content/docs/firefox-extension.md`
